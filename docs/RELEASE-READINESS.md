## 2. 지금 되어 있는 것

출시 판단의 바탕이 되는 현재 상태다.

- **자료 보호**: 원자적 쓰기, 저장소 잠금, 기간 계층 백업(최근 20개 + 2주 일별 + 8주 주별), 밖에서 바뀐 저장소를 재시작 없이 다시 읽기, 더 새로운 형식은 복구 대신 업데이트 안내, 이전 이름의 저장소·동기화 폴더·전체 백업·설정 폴더·화면 저장 키 자동 인계.
- **읽기·번역**: 원문 배치를 유지한 번역과 PDF 저장, 수식·표·참고문헌의 원문 유지, 그림 슬라이드의 로컬 OCR(영어), 조각난 글자층 스캔본, 목록 항목 배치, 번역 결과 상태와 "문제 있는 쪽만 다시 번역", 원문·번역의 새 창(보기 전용).
- **기록**: 메모·주석(넓은 편집, AI 질문·편집), 필기, 노트북, AI 요약·질문(근거 쪽 표시), AI 태그 추천.
- **자료 관리**: 중복 PDF 안내, 병합, 영구 삭제(휴지통으로), 옮긴 파일의 기록 재연결, 최근 저장소 메뉴.
- **앱 형태**: 응용 프로그램 메뉴, 단축키 도움말, 첫 실행 안내, 창 상태 기억, 번역 완료 알림, 이름·로고(βnote).
- **진단**: 로컬 진단 기록과 화면 오류 안내.
- **시험**: 단위 565개, 실제 앱을 띄우는 스모크 49종. 스모크는 패키지가 없으면 소스로 실행한다.

실제 저장소 사본(논문 73편, 번역 75건, 1,371쪽)으로 확인한 번역 배치: 겹침으로 원문 처리되는 문단 0개, 칸에서 잘린 번역 0개. 다시 번역해야 풀리는 쪽이 14개 문서 24쪽 남아 있다(미번역 31, 문단 대응 21).

## 3. 추가 — 출시 전에 만들어야 할 것

### A-1 진단 기록과 오류 안내 — 구현됨, 실기기 확인 남음

- **지금**: 로컬 진단 기록(`logs/`, 1.5MB까지, 경로·키·본문 제외), 도움말의 "진단 정보 복사"·"로그 폴더 열기", 화면이 죽거나 멈췄을 때의 안내와 다시 불러오기가 있다([개발 문서](DEVELOPMENT.md) "진단 기록과 오류 안내").
- **남은 일**: Windows 패키지에서 화면이 죽었을 때 안내가 뜨고 돌아오는지 확인(A-5).

### A-2 설치 프로그램, 서명, 업데이트 알림

- **지금**: `scripts/package.mjs`가 폴더만 만든다(Linux·Windows). 설치 프로그램, 코드 서명, 새 버전 확인이 없다. 릴리스 워크플로는 정식 릴리스로 올린다.
- **할 일**
  - Windows: 설치 프로그램과 휴대용 zip. Ubuntu: AppImage 또는 deb. 지원 OS 버전 명시.
  - 아이콘·제품 이름·저작권 표시·Windows `AppUserModelId`.
  - 코드 서명(4절의 결정에 따름). 서명 없이 내면 경고 화면과 해시 확인 방법을 설치 안내에 적는다.
  - "새 버전 있음" 알림. 앱 안에서 버전과 서드파티 고지 보기.
- **완료 기준**: 깨끗한 Windows와 Ubuntu 22.04에서 설치 → 실행 → 저장소 연결 → 제거까지 확인한 기록.

### A-3 Windows에서 돌아가는 자동 시험

- **지금**: CI는 `ubuntu-24.04`에서 `npm test`, 고지 점검, 두 OS 패키징, `test:desktop`만 돈다. 주 대상인 Windows에서는 아무것도 실행되지 않는다. 스모크 24종 가운데 23종은 CI에 없다.
- **할 일**
  - 푸시마다 `npm test`, `check:dist`, 빠른 스모크.
  - Windows 러너에서 패키지 빌드와 `test:desktop`, `test:ink`, `test:sync`, `test:ocr`, `test:view-window`.
  - 릴리스는 스모크 전체가 통과해야 올린다.
- **완료 기준**: 릴리스 산출물마다 OS별 시험 결과가 남는다.

### A-4 라이선스와 사용자 문서

- **지금**: AGPL-3.0-only로 정했다(`LICENSE`, `package.json`). 상업 라이선스 안내(`COMMERCIAL.md`), 기여자 동의 초안(`CLA.md`, 아직 적용하지 않음: 코드 기여는 당분간 받지 않는다), 서드파티 고지가 있다. CLA 초안과 상업 라이선스 문구는 법률 검토를 받지 않았고, `COMMERCIAL.md`의 문의 연락처가 비어 있다. 사용자용 설명은 README의 기능·설치 절뿐이다.
- **할 일**
  - 개인 사용 조건과 상업 라이선스 문구 확정(4절).
  - 사용자 안내: 저장소가 무엇인지와 여러 PC에서 쓰는 법, 번역 연결 세 가지(ChatGPT 계정·API 키·로컬 모델)와 무엇이 어디로 전송되는지, 백업과 복구, 알려진 제한(PDF 100MB, 번역 500쪽, OCR 영어).
  - 개인정보 안내: 외부로 나가는 것은 번역·AI 요청과 서지 조회뿐이라는 점, 요청에 쪽 그림이 포함되는 경우(OCR·스캔본).
- **완료 기준**: 앱의 도움말에서 문서로 갈 수 있고, 설치 안내만 보고 처음 쓰는 사람이 번역까지 간다.

## 4. 제외·보류 — 첫 출시에서 뺄 것

ChatGPT 계정 연결과 기기 간 동기화는 실험 기능이 아니라 정식 기능으로 낸다(결정됨). 동기화의 실제 클라우드 클라이언트 확인은 A-5에 둔다.

| 항목 | 지금 | 제안 |
| --- | --- | --- |
| **자동 업데이트** | 없음 | 첫 출시는 알림만. 서명이 자리 잡은 뒤 도입 |
| **다른 번역 결과 언어** | 화면은 한국어·영어, AI 답변은 8개 언어([언어 설정](DEVELOPMENT.md#언어-설정)). 번역 결과는 한국어만이고, 영어 화면에서 운영체제 언어로도 정해지지 않을 때 처음 번역할 때 한 번 묻는다. 다른 언어를 위한 구조(언어 프로필, 언어별 캐시 이름, 설정 자리)는 준비됨. OCR은 영어만 | 첫 출시의 번역 결과는 한국어만. 중국어 간체·일본어·중국어 번체·유럽어 순으로 다음 판 |
| **사용 통계** | 없음 | 넣지 않는다. 로컬 진단 로그만(A-1) |

개발용 기능(`APP_TEST_SOURCE`, `APP_DEBUG_IPC`, 개발 상태 복원)은 패키지에서 꺼져 있는지 A-5에서 함께 확인한다.

## 7. 바꾸지 말아야 할 것

- **화면 프로세스 격리**: `sandbox`, `contextIsolation`, 엄격한 CSP, 탐색·권한 요청 차단, 요청자 확인(`register()`). 노트북 창과 보기 창은 정해진 요청만 부른다.
- **원자적 쓰기**: 임시 파일 → fsync → `rename`. 새 저장 경로도 같은 함수를 쓴다.
- **저장소 잠금과 닫기 순서**: 번역 쓰기 → 필기 → 노트북 → 종료 백업 → 잠금 해제.
- **자격증명**: API 키와 토큰은 주 프로세스에만 두고 OS 보안 저장소로 암호화한다.
- **번역 캐시 정합성**: 프롬프트와 캐시 버전은 `translation-policy.cjs`에서 함께 바꾼다.
- **PDF 원본 불변**: 원본은 수정하지 않는다. 필기 포함 출력은 새 파일로만 만든다.
- **식별자와 이전 이름 인계**: `.betanote/`, `betanote-sync`. 보이지 않는 내부 이름(`window.appApi`, `app://`, `app-*` 클래스·이벤트·화면 저장 키, `APP_*` 오류 코드·환경 변수)은 이름과 무관하다(`betanote-*` 화면 저장 키는 `app-*`로 넘겨받는다). 이전 이름이 남긴 것은 `legacy.cjs`·`storage-keys.js`가 넘겨받고, 이전 이름은 그 둘과 번역 자리표시자에만 남는다(`tests/names.test.cjs`, 개발 문서의 "이전 이름에서 넘겨받기").
- **저장된 번역의 보존**: 문단을 읽는 규칙을 바꿔도 옛 번역은 다시 번역하기 전까지 보인다(`reconcilePage`, `canonicalFor`).

### 이름이 바뀐 첫 판의 릴리스 안내

이름을 βnote로 바꾼 첫 판의 릴리스 안내(`scripts/archive.py`가 `docs/release/name-change.md`를 이름 파일 값으로 채워 `RELEASE-NOTES.md`에 넣는다. 그 파일이 없으면 이 절도 없다)와 README에 사용자에게 다음을 알린다.

- 이전 이름(Papi Note, knote)으로 만든 저장소·설정·동기화 폴더는 새 앱이 처음 열 때 넘겨받는다. 이전 폴더는 지우지 않는다.
- **동기화하는 PC는 모두 함께 새 앱으로 바꾼다.** 한 대라도 이전 앱을 쓰면 그 PC는 이전 이름의 폴더를 따로 쓴다.
- **노트북 화이트보드는 모든 PC가 새 판일 때 쓴다.** 이전 판은 화이트보드가 든 노트북을 열지만 저장하지 못한다(고친 것이 닫을 때 사라진다).
- **Linux에서는 API 키와 ChatGPT 연결을 한 번 다시 해야 할 수 있다**(보안 저장소의 키가 앱 이름에 묶여 있다). 앱이 시작할 때와 설정에서 알려 준다.
- **기본 인용 키가 `beta<번호>`로 바뀐다.** 원고에서 예전 기본 키(`papi<번호>`, `knote<번호>`)로 인용했다면 그 키를 자료의 인용 키 칸에 적는다.

## 9. 작업할 때 지킬 규칙

- 변경 전 현재 브랜치와 사용자 변경을 확인한다. 기능, 저장 형식, 기존 사용자 자료를 보존한다(AGENTS.md).
- 저장 형식이나 문단 규칙을 건드리는 변경은 실제 저장소 사본으로 확인한다. 원본 저장소에서 시험하지 않는다.
- 보고에는 실제 실행 결과와 환경 제약을 구분해 적는다. 모의 모델 통과를 번역 품질로 적지 않는다.
- `dist/`는 직접 고치지 않는다. 화면 변경은 `desktop/`의 원본에서 한다.
