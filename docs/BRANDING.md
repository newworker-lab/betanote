# 이름과 브랜딩 제안 (검토용)

작성일: 2026-11-10 KST · 기준: `claude` 브랜치 `dd1cf5d`

구현된 프로그램의 기능을 근거로 이름, 소개 문구, 메시지, 시각 방향을 정리한다. **0절이 현재 기준이다.** 1~10절은 이름을 정하던 때의 검토 기록이라 그때의 후보와 권장이 그대로 남아 있다. 이름이 바뀌어 온 과정은 "이름 이력" 절.

## 0. 현재 방향: βnote

이름은 **βnote**(그리스 문자 β + note), 한글로 **베타노트**다. 화면, 창 제목, 실행 파일, 저장소 폴더, 설정 폴더까지 이 이름으로 바꿨다(개발 문서의 "이름과 식별자"). 상표·도메인 확인은 아직 전문가 확인 전이다(출시 검토 문서의 결정 8).

### 표기

- 문장 안에서는 `βnote`로 쓴다. β는 소문자 그대로이고 문장 맨 앞에서도 대문자 `Β`로 바꾸지 않는다.
- 이름을 처음 소개하는 자리(README 첫머리 등)에서 한 번 `βnote(베타노트)`로 쓴다. 화면 글자 안에서는 `βnote`만 쓴다.
- 그리스 문자를 쓸 수 없는 자리는 `BetaNote`(설정 폴더, `productName`)와 `betanote`(실행 파일, 폴더, 식별자)로 쓴다. 폴더 이름에는 그리스 문자를 쓰지 않는다.
- 슬로건: **원문 그대로 번역해 읽고, 묻고, 그 위에 쓴다.** 보조: 번역은 원문 자리에, AI와 나눈 질문과 답은 논문 옆에. 내 모델로 쓰는 논문 스터디 노트.
- 슬로건의 세 동작은 각각 실제 기능을 가리킨다. **번역해 읽고**는 원문 배치 그대로의 번역, **묻고**는 논문 질문·선택 문장 설명·구조화 요약(답은 AI 기록과 주석으로 그 논문에 남고 근거 쪽으로 이동한다), **그 위에 쓴다**는 원문·번역 위의 필기와 메모다. 짧게 줄여야 하는 자리에서는 "읽고, 묻고, 쓴다."를 쓴다.

### 로고

`brand/` 폴더에 있다. 미리보기는 `brand/brand-sheet.png`. PNG·ICO·배너·미리보기는 SVG에서 `scripts/brand.mjs`(Playwright의 Chromium)로 다시 만든다.

| `betanote-logo.svg`, `betanote-logo-dark.svg` | 가로형 로고(기호 + 글자 로고). 밝은 바탕용과 어두운 바탕용 |

기호와 글자 로고의 규칙:

- **기호**: 파란 둥근 사각형 안에 흰 β(획 굵기 7, 64 격자), 오른쪽 위에 노란 점. 16px에서는 β와 노란 점만 보이면 된다.
- **글자 로고**: 굵은 β(획 9)와 가늘고 옅은 `note`(획 5, 밝은 바탕에서 Ink의 72%), 글자 아래 노란 형광펜 밑줄(두께 약 4.5, 양 끝은 사선). β의 꼬리는 밑줄을 지나 아래로 내려간다. 노란 점은 기호에만 있고 글자 로고에는 없다.
- **어두운 바탕**: β는 흰색, `note`는 `#c9cdd2`(투명도 없음), 밑줄은 같은 노랑.
- **앱 화면의 로고**는 `brand/`의 기호(`<id>-mark.svg`)와 글자 로고(`<id>-wordmark.svg`) SVG를 빌드가 그대로 실어 그린다(`scripts/build.mjs`의 `dist/app-logo.js`, `desktop/app.js`의 `logo()`). 앱은 Inter를 싣지 않아 글꼴로 쓰면 PC마다 β 모양이 달라지기 때문이다. 글자 로고의 어두운 잉크(`#191f28`)는 화면 글자색이 되고, `class="logo-word-note"`를 단 `note`는 더 옅게(`desktop/app.css`), 밑줄은 밝은·어두운 화면 모두 같은 노랑이다. 화면은 글자 로고 파일의 여백(양옆 6, 위아래 12)을 빼고 그린다.
- 기호 둘레에는 기호 너비의 1/4 이상 여백을 둔다.
- 하지 않는 것: 색 바꾸기, 기울이기, 그림자·그라데이션, 노란 점이나 밑줄을 다른 색으로 바꾸거나 옮기기, 기호를 늘이거나 자르기, 글자 로고를 글꼴로 다시 쓰기.

### 소개 이미지의 원칙

- 대표 장면은 **원문과 번역이 나란히 있고, 번역 위에 형광펜과 손글씨, 옆에 질문과 답 카드가 있는 모습**이다. 슬로건의 세 동작(번역해 읽고, 묻고, 쓴다)이 한 장에 보인다.
- 화면 캡처를 쓸 때는 실제 화면을 쓴다. 번역 품질을 보증하는 문구("정확한", "전문가 수준")는 넣지 않는다(5절).
- 배너의 추상 그림(회색 줄의 원문, 같은 자리의 번역, 노란 형광펜 줄, 파란 펜 선, 근거 쪽 표시가 붙은 질문·답 카드)은 캡처를 쓸 수 없는 자리에 쓴다.
- AI에 관한 문구는 "묻고 답을 남긴다", "근거 쪽으로 이동한다"까지만 쓴다. 답이 옳다는 뜻의 표현은 쓰지 않는다(5절).

### 적용된 곳

- 화면의 로고는 빌드가 `brand/<id>-mark.svg`·`brand/<id>-wordmark.svg`에서 만든 `dist/app-logo.js`와 `desktop/app.css`의 `.logo`. 창 아이콘은 `scripts/build.mjs`가 `brand/png/<id>-icon-256.png`를 `dist/icon.png`로 복사한 것, 패키지 아이콘은 `scripts/package.mjs`의 `icon`(`brand/<id>` → `.ico`·`.png`). `<id>`는 이름 파일(`core/app-name.json`)의 `id`이고, `node scripts/brand.mjs`가 같은 이름으로 PNG·ICO·배너·시트를 만든다.
- 이름 충돌은 웹 검색으로만 봤다. 결정 전에 앱스토어·도메인·KIPRIS를 직접 확인한다.
- 이름은 이름 파일 `core/app-name.json` 한 곳에 둔다(화면 이름 `name`, 설정 폴더 `product`, 폴더·실행 파일·그림 파일 `id`, 기본 인용 키 `citekeyPrefix`, 이전 이름 `history`). 이름을 바꿀 때는 `docs/DEVELOPMENT.md`의 "이름 바꾸기 절차"를 따른다: 이름 파일과 `package.json`, `brand/`의 그림, 글만 고치면 된다.

## 이름 이력

- **knote**: 처음의 가칭. 태그 `v0.3.0`이 이 이름이다. 같은 이름의 제품이 여럿 있어 바꿨다(2.1절).
- **Papi Note**: 제품군 `Papi`와 이 프로그램 `Papi Note`, 구상 중이던 `Papi Voice`로 정했던 이름. 기호는 파란 사각형의 흰 소문자 p와 i의 노란 점이었다. 태그된 판은 없다. 제품군 구성(PRODUCT FAMILY)은 βnote로 바꾸며 정리했다.
- **βnote**(2026-11-16): 상표·검색 분석 끝에 정한 지금 이름. 보이는 이름부터 폴더·식별자까지 모두 바꿨고, 이전 두 이름으로 만든 자료는 새 앱이 처음 만날 때 넘겨받는다(개발 문서의 "이전 이름에서 넘겨받기").

## 1. 이 프로그램이 무엇인가

한 문장: **외국어 논문을 원래 모양 그대로 한국어로 읽고, 그 위에 쓰고, 내 폴더에 쌓아 두는 데스크톱 연구 도구.**

코드에서 확인한, 브랜드의 근거가 되는 사실은 다음과 같다.

| 구분 | 실제로 구현된 것 | 사용자에게 주는 것 |
| --- | --- | --- |
| **읽기** | 원문 PDF의 문단 위치·글꼴·수식·그림을 유지한 채 번역을 같은 자리에 겹쳐 보여 준다. 원문·번역·동시보기 전환, 번역 PDF 저장 | 그림·수식·표를 원문과 대조하며 번역본을 읽는다. 번역 텍스트만 따로 떼어 읽지 않아도 된다 |
| **쓰기** | 원문과 번역 위에 펜·형광펜·도형·텍스트 상자·문장 강조. 논문 옆 A4 노트북, 메모(Markdown·수식) | 종이에 하듯 논문 위에 바로 쓴다. 필기는 재번역 없이 그대로 복원된다 |
| **묻기** | 구조화 요약, 선택 문장 설명, 논문 질문, 그림 설명, 여러 논문 비교. 답마다 근거 쪽을 연결하고 근거가 없으면 "근거 부족"으로 표시 | AI의 답을 원문 위치에서 확인한다 |
| **모으기** | 서지정보 자동 채우기(DOI·Crossref·DataCite), RIS·BibTeX·CSL JSON 교환, APA·Vancouver 인용, 태그·컬렉션·전문 검색 | 읽은 논문이 인용할 수 있는 자료로 정리된다 |
| **지키기** | 자료는 사용자가 고른 폴더에 파일로 저장. 원본 PDF는 바꾸지 않음. 자동 백업·전체 백업·휴지통·여러 PC 동기화 폴더 | 서비스가 사라져도 내 자료는 내 폴더에 남는다 |
| **고르기** | ChatGPT 계정, GPT·Claude·Gemini API 키, 로컬 모델(Ollama 등) 중 선택. 연결 사이 자동 전환·자동 과금 없음 | 번역에 쓸 모델과 비용을 사용자가 정한다. 로컬 모델이면 논문이 PC 밖으로 나가지 않는다 |

### 다른 도구와 다른 점

1. **번역이 원문 자리에 놓인다.** 일반 번역기는 글만 옮기고, PDF 번역 서비스는 결과 파일을 돌려준다. 이 프로그램은 읽는 화면 자체가 번역본이고, 원문과 같은 좌표를 쓴다.
2. **번역 위에 쓴 필기가 남는다.** 번역 바탕을 보관하므로 다시 번역하지 않아도 필기 위치가 유지된다.
3. **읽기 도구와 서지 관리가 한 프로그램이다.** 번역해 읽는 도구와 서지 관리 도구를 따로 오가지 않는다.
4. **계정도 서버도 없다.** 저장소는 평범한 폴더이고, 번역 모델은 사용자가 가져온다.

## 2. 이름

### 2.1 현재 이름의 문제

`knote`는 README가 밝힌 대로 가칭이다. 같은 이름과 거의 같은 이름의 제품이 이미 여럿 있다. 검색에서 확인한 것만 해도 iOS 메모 앱 Knote, 업무용 노트 서비스 Knote, 독서 노트 앱 Knotes, macOS 메모 앱 Knotes, 오래된 데스크톱 프로그램 KNote가 있다. 검색으로 찾기 어렵고 상표 분쟁 위험이 있어 정식 이름으로는 권하지 않는다.

### 2.2 후보

| 후보 | 뜻과 연결 | 장점 | 약점 |
| --- | --- | --- | --- |
| **행간** (Haenggan) | 글의 줄과 줄 사이. "행간을 읽다". 번역이 원문 줄 자리에 놓이고, 사용자는 그 사이에 쓴다 | 한국어 사용자에게 뜻이 바로 전해진다. 번역·필기·근거 확인 세 가지를 한 단어로 묶는다. 같은 이름의 앱은 검색에서 나오지 않았다 | 일반 명사라 단독 상표 등록이 어려울 수 있다. 영문 표기가 낯설다 |
| **Glossa** (글로사) | gloss: 본문 줄 사이나 여백에 적는 번역·풀이. glossary(용어집)와 어원이 같다 | 제품의 핵심 동작을 정확히 가리키는 단어. 해외에서도 읽힌다. 용어집 기능과 이어진다 | 같은 이름의 언어학 학술지가 있고, GlossPage·GlossBook 같은 번역 앱이 있다. 한국어 사용자에게는 설명이 필요하다 |
| **Bifolio** (바이폴리오) | 한 장을 접어 두 쪽이 된 종이. 원문과 번역이 나란히 있는 모습 | 같은 이름의 소프트웨어는 검색에서 나오지 않았다. 종이·책의 느낌 | 뜻을 아는 사람이 적다. Bitfolio(투자 앱)와 한 글자 차이 |
| **knote** 유지 | k(한국어) + note, knot(엮다) | 지금 코드·문서와 일치 | 2.1의 충돌 |

### 2.3 권장

**행간**을 권한다. 표기는 한글 `행간`을 주 이름으로, 영문은 `Haenggan`으로 한다.

- 이 프로그램의 화면 언어와 번역 대상이 한국어이고, 첫 사용자는 외국어 논문을 읽는 한국어 연구자다. 그 사람에게 설명 없이 통하는 이름이다.
- 세 가지 핵심 동작에 모두 닿는다. 번역은 원문의 **행** 자리에 놓이고, 필기는 행 **사이**에 쓰이며, AI는 **행간을 읽되** 근거 쪽을 보여 준다.
- 일반 명사의 약점은 로고와 설명어를 붙여 보완한다. 등록은 `행간` 단독이 아니라 도형 결합이나 `행간 리더` 같은 결합 표장으로 검토한다.

해외 사용자를 처음부터 겨냥한다면 **Glossa**가 차선이다.

**출시 계획에 따른 보정(2026-11-10)**: 지금은 한국어 사용자용이고, 이후 중국·일본·유럽 등 영어가 모국어가 아닌 나라에 낼 계획이다. 이 경우 이름을 두 번 바꾸지 않으려면 처음부터 **Glossa** 같은 언어 중립 이름을 쓰는 편이 낫다. `행간`은 한국어 판의 설명어나 슬로건("행간까지 읽는 논문 리더")으로 살릴 수 있다. 슬로건 "원문 그대로, 한국어로 읽는다"는 언어별로 "원문 그대로, 내 언어로 읽는다"로 일반화한다.

### 2.4 확인이 필요한 것

- 이번 확인은 웹 검색 몇 건뿐이다. **상표 조사가 아니다.** 결정 전에 KIPRIS에서 제9류(소프트웨어)·제42류(SaaS) 선행 상표를, 해외 출시를 한다면 해당국 상표를 확인한다.
- 도메인과 GitHub·스토어 계정 이름의 사용 가능 여부는 확인하지 않았다.

## 3. 소개 문구

이하 문구는 `행간` 기준이다. 다른 이름을 고르면 이름만 바꿔 쓴다.

| 용도 | 문구 |
| --- | --- |
| 슬로건 | **원문 그대로, 한국어로 읽는다.** |
| 대안 슬로건 | 논문의 행간까지, 내 폴더에. · 읽고, 쓰고, 남기는 논문 리더. |
| 한 줄 소개 | 논문 PDF를 원래 배치 그대로 번역해 읽고, 그 위에 필기하고, 서지와 함께 내 폴더에 정리하는 데스크톱 앱. |
| 두 문장 소개 | 행간은 외국어 논문을 그림·수식·단 구성 그대로 한국어로 보여 줍니다. 번역 위에 바로 필기하고, AI의 답은 근거 쪽에서 확인하며, 모든 자료는 내 컴퓨터의 폴더에 남습니다. |

### README·배포 페이지용 소개(초안)

> **행간 — 원문 그대로, 한국어로 읽는 논문 리더**
>
> 번역기에 문단을 붙여 넣고, 그림은 원문에서 다시 찾고, 메모는 또 다른 앱에 적던 일을 한 화면으로 모았습니다.
>
> - **배치 그대로 번역** — 문단·수식·그림이 원문과 같은 자리에 있습니다. 원문과 나란히 보거나 번역 PDF로 저장합니다.
> - **번역 위에 필기** — 펜, 형광펜, 텍스트 상자, 논문 옆 노트북. 다시 번역하지 않아도 필기는 그대로입니다.
> - **근거가 보이는 AI** — 요약·질문·그림 설명의 답마다 근거 쪽으로 이동합니다. 근거가 없으면 없다고 표시합니다.
> - **서지 관리** — DOI로 서지정보를 채우고, BibTeX·RIS로 주고받고, APA·Vancouver로 인용합니다.
> - **내 폴더, 내 모델** — 자료는 내가 고른 폴더에 파일로 남습니다. 번역 모델은 ChatGPT 계정, API 키, 로컬 모델 중에서 고릅니다.

## 4. 대상과 자리매김

- **첫 대상**: 영어 논문을 매주 읽는 한국어 사용자. 대학원생, 연구원, 기업 연구·개발자, 논문을 읽는 임상의.
- **이들이 지금 쓰는 조합**: PDF 뷰어 + 번역기 + 서지 관리 도구 + 필기 앱. 창을 오가며 문맥을 잃고, 번역과 메모가 흩어진다.
- **자리매김 문장**: 외국어 논문을 읽는 한국어 연구자에게, 행간은 번역·필기·서지를 한 화면에 둔 논문 리더다. 번역 결과를 따로 받아 보는 도구와 달리 원문 배치 위에서 읽고 쓰며, 자료는 사용자의 폴더에 남는다.

## 5. 핵심 메시지

메시지는 세 기둥으로 묶는다. 각 기둥의 문구는 4절의 사실에서만 가져온다.

| 기둥 | 주 문구 | 뒷받침 |
| --- | --- | --- |
| **그대로 읽는다** | 원문 모양 그대로 번역 | 배치 유지 번역, 동시보기, 번역 PDF, 용어집·번역 요청 사항, 문단별 교정과 이력 |
| **바로 쓴다** | 읽는 자리에서 필기와 메모 | 원문·번역 필기, 문장 강조, 노트북, 메모, 주석 모아 보기, 근거가 연결된 AI |
| **내 것으로 남는다** | 내 폴더, 내 모델 | 폴더 저장소, 원본 PDF 불변, 백업·복원·동기화 폴더, 연결 선택, 로컬 모델 |

### 쓰지 말아야 할 표현

구현 상태로 뒷받침되지 않는 말은 쓰지 않는다([출시 검토 문서](RELEASE-READINESS.md) A-5).

| 쓰지 않는다 | 이유 | 대신 |
| --- | --- | --- |
| "정확한 번역", "전문가 수준 번역" | 번역의 의미 품질은 실제 모델로 검증되지 않았고 모델에 따라 달라진다 | "원문 배치 그대로", "원문과 대조하며 읽는" |
| "AI가 논문을 이해" | 근거 연결은 검증하지만 답의 옳고 그름은 보장하지 않는다 | "근거 쪽을 함께 보여 주는" |
| "무료 번역" | API 키 연결은 공급자 요금이 든다 | "쓰는 모델과 비용을 직접 고르는" |
| "어디서나", "모든 기기" | Windows와 Ubuntu 데스크톱만 지원한다 | "Windows·Ubuntu 데스크톱" |
| "자동 동기화", "클라우드" | 동기화는 사용자가 정한 공유 폴더를 통한다 | "여러 PC에서 이어 쓰는 동기화 폴더" |
| "스캔 논문 지원" | OCR은 영어만 지원한다 | 지원 범위를 그대로 적는다 |

## 6. 말투

- **차분하고 구체적으로.** 기능을 사실대로 말한다. 느낌표와 과장 부사를 쓰지 않는다.
- **연구자의 말로.** "생산성", "혁신" 대신 "문단", "수식", "근거 쪽", "서지".
- **자료의 안전을 먼저.** 오류 문구는 무슨 일이 있었는지, 자료는 안전한지, 무엇을 하면 되는지 순서로 쓴다.
- 화면 문구는 지금처럼 `~합니다` 체를 유지한다. 용어는 `자료 저장소`(줄여서 `저장소`)로 통일한다.

| 상황 | 이렇게 | 이렇게는 아니다 |
| --- | --- | --- |
| 번역 완료 | 번역을 마쳤습니다. 확인하지 못한 문단 2개는 원문으로 표시합니다. | 번역 완료! 🎉 |
| 저장 실패 | 저장하지 못했습니다. 입력한 내용은 화면에 남아 있습니다. 다시 시도하세요. | 오류가 발생했습니다. |
| 기능 소개 | 번역 위에 쓴 필기는 다시 번역하지 않아도 그대로 남습니다. | 혁신적인 AI 필기 경험 |

## 7. 시각 방향

지금 화면이 쓰는 값을 기준으로 삼고, 이름에 맞춰 로고만 새로 만든다.

| 요소 | 현재(코드) | 제안 |
| --- | --- | --- |
| 주 색 | `#1b64da`(파랑), 옅은 배경 `#e8f3ff` | 유지. 이름을 `행간 블루`로 붙인다 |
| 글자·바탕 | 글자 `#191f28`, 보조 `#6b7684`, 바탕 `#f2f4f6`, 면 `#fff` | 유지 |
| 강조 색 | 형광펜 노랑(필기 도구) | 로고와 소개 이미지의 보조 색으로 쓴다. "읽은 흔적"을 뜻한다 |
| 화면 글꼴 | Inter, Noto Sans KR | 유지 |
| 본문 글꼴 | Noto Serif KR·Noto Sans KR(번역 본문) | 워드마크에 Noto Serif KR을 써서 "논문 본문" 느낌을 낸다 |
| 로고 | 파란 둥근 사각형 안의 `k` + `knote` 글자 | 아래 개념으로 교체 |

### 로고 개념

- **기호**: 가로줄 세 개. 위아래 두 줄은 본문의 행(짙은 색), 가운데 한 줄은 그 사이에 쓴 것(파랑 또는 형광펜 노랑)이고 길이가 조금 짧다. 16px 아이콘에서도 읽힌다.
- **워드마크**: `행간`을 세리프로, 영문 병기 시 `Haenggan`을 산세리프 소문자로.
- **앱 아이콘**: 지금의 파란 둥근 사각형을 유지하고 안의 `k`를 세 줄 기호로 바꾼다. 기존 사용자가 같은 프로그램임을 알아본다.
- **금지**: 책·돋보기·전구·로봇 같은 흔한 그림, 그라데이션, 기호와 글자를 겹치는 배치.

로고 파일은 만들지 않았다. 이름이 확정되면 SVG로 제작하고 패키지 아이콘(`.ico`, `.png`)까지 함께 넣는다. 지금 패키지에는 아이콘 지정이 없다(출시 검토 문서 A-03).

### 소개 이미지에 담을 장면

1. **동시보기**: 왼쪽 원문, 오른쪽 번역. 수식과 그림이 같은 자리에 있는 장면. 이 프로그램을 한 장으로 설명한다.
2. **번역 위 필기**: 번역 문단에 형광펜과 손글씨 메모.
3. **근거로 이동**: AI 답의 쪽 표시를 눌러 원문 위치가 강조된 장면.
4. **라이브러리**: 태그·읽기 상태·서지가 보이는 목록.

## 8. 기능 이름 정리

화면에 이미 쓰이는 이름을 그대로 브랜드 용어로 삼는다. 새 이름을 만들지 않는다.

| 화면 이름 | 소개할 때의 설명 |
| --- | --- |
| 자료 저장소 | 논문과 기록을 함께 두는 내 폴더 |
| 원문 · 번역 · 동시보기 | 같은 배치의 세 가지 보기 |
| 노트북 | 논문 옆에 펼치는 A4 연구 노트 |
| 메모 · 주석 | 논문에 붙이는 글과, 특정 쪽·문장에 붙이는 글 |
| 요약 · 질문 · 그림 설명 | 근거 쪽이 연결된 AI 도구 |
| 용어집 · 번역 요청 사항 | 내 분야의 용어와 문체를 번역에 반영하는 설정 |
| 동기화 폴더 | 여러 PC에서 같은 저장소를 이어 쓰는 방법 |

## 9. 이름을 바꿀 때의 적용 순서

개발 문서의 "호환을 위해 유지하는 식별자"를 따른다. **보이는 이름만 바꾸고 내부 식별자는 그대로 둔다.**

| 단계 | 바꾸는 것 | 주의 |
| --- | --- | --- |
| 1 | 화면의 로고·창 제목(`knote`, `knote 노트북`), 시작 화면, 설정 문구, 알림 제목 | `desktop/app.js`의 `logo()`, `main.cjs`의 창 `title` |
| 2 | README, COMMERCIAL, CONTRIBUTING, 릴리스 제목과 압축 파일 이름 | 릴리스 워크플로의 "desktop prototype" 문구도 함께 |
| 3 | 패키지의 제품 이름·실행 파일 이름·아이콘 | `scripts/package.mjs`의 `name`. 실행 파일 이름이 바뀌면 스모크 시험의 경로도 바꾼다 |
| 바꾸지 않음 | `package.json`의 `name`, `.knote/` 폴더, `knote://`, `window.knote`, `knote-*` 저장 키, 백업 표식 | `name`을 바꾸면 설정·API 키·색인 위치가 바뀌어 사라진 것처럼 보인다. 바꿔야 하면 기존 위치를 읽어 옮기는 처리를 먼저 넣는다 |

제품 표시 이름은 `package.json`의 `productName`을 새로 두어 `name`과 분리하는 방법을 권한다. 이 경우에도 userData 경로가 `productName`을 따르게 되므로, 기존 경로를 유지하도록 `app.setPath('userData', …)`를 명시하고 실기기에서 설정이 그대로 열리는지 확인한다.

## 10. 결정이 필요한 사항

| 결정 | 권장 |
| --- | --- |
| 정식 이름 | 행간 (차선 Glossa) |
| 영문 표기 | Haenggan. 해외 출시 계획이 생기면 다시 검토 |
| 슬로건 | 원문 그대로, 한국어로 읽는다. |
| 상표 조사 | 결정 전에 KIPRIS 확인 |
| 로고 제작 | 이름 확정 뒤 세 줄 기호 안으로 SVG 제작 |
| 코드 적용 | 이름 확정 뒤 9절의 1~3단계 |
